# Как развернуть Astro в интернет

Проект состоит из двух частей, разворачиваются раздельно:

- **backend/** — Express-прокси к AstrologyAPI, держит ключ в секрете → хостинг для Node.js (Render).
- **frontend/** — Vite/React, после сборки просто статика → статический хостинг с CDN (Vercel).

В корне уже лежат готовые конфиги: `render.yaml` (Render подхватит его автоматически при создании Blueprint) и `frontend/vercel.json`.

## Шаг 1. Залить код на GitHub

В PowerShell, в папке `C:\Users\mbobr\Astro`:

```powershell
git init
git add .
git commit -m "Initial commit"
```

Проверьте перед этим `git status` — в списке НЕ должно быть `backend/.env` и `frontend/.env` (в них ключи/локальные адреса). Если всё же попали — сначала поправьте `.gitignore`, `git rm --cached backend/.env frontend/.env`, и закоммитьте заново.

Создайте пустой репозиторий на github.com (без README/gitignore — они уже есть), затем:

```powershell
git remote add origin https://github.com/ВАШ_ЛОГИН/astro.git
git branch -M main
git push -u origin main
```

## Шаг 2. Backend → Render

1. render.com → **New → Blueprint** → подключите репозиторий astro.
2. Render сам прочитает `render.yaml` и создаст сервис `astro-backend` с root directory `backend`, командами `npm install` / `npm start`.
3. Откроется запрос на два секрета — впишите:
   - `ASTROLOGY_API_KEY` = ваш реальный ключ с astrologyapi.com
   - `ALLOWED_ORIGIN` = пока оставьте `http://localhost:5173`, вернётесь на шаге 4
4. Deploy. Получите адрес вида `https://astro-backend-xxxx.onrender.com` — проверьте, что `https://astro-backend-xxxx.onrender.com/api/health` отвечает `{"ok":true}`.

Бесплатный тариф Render засыпает после 15 минут без запросов, первый запрос после этого грузится около минуты — для теста ок, для постоянной нагрузки позже можно перейти на платный (от $7/мес).

## Шаг 3. Frontend → Vercel

1. vercel.com → **New Project** → тот же репозиторий.
2. Root Directory: `frontend` (Framework Preset Vite определится сам, `vercel.json` уже задаёт build/output на всякий случай).
3. Environment Variables → `VITE_API_BASE` = адрес backend из шага 2 (`https://astro-backend-xxxx.onrender.com`).
4. Deploy. Получите публичный адрес вида `https://astro-frontend.vercel.app`.

## Шаг 4. Вернуться в Render

В настройках `astro-backend` → Environment → поменяйте `ALLOWED_ORIGIN` на адрес из Vercel (`https://astro-frontend.vercel.app`) → Save (сервис передеплоится сам).

## Проверка

Откройте адрес Vercel в браузере, попробуйте построить карту — если backend ещё «спит» (Render free), первый запрос может занять ~30-60 секунд.

## На будущее

- Любой git push в main — автоматически передеплоит обе части (и Render, и Vercel следят за репозиторием).
- Ключ AstrologyAPI — trial, у него лимит запросов. Для публичного использования проверьте лимит в личном кабинете astrologyapi.com и при необходимости перейдите на платный план.
- Свой домен вместо `*.vercel.app` — Vercel → Settings → Domains, укажете DNS у регистратора.

## Шаг 5. Аккаунты, лимит пакета и оплата (ЮKassa)

Это включает реальные аккаунты (вход по коду на email), пакет из `PACKAGE_QUOTA` (по умолчанию 25) расширенных
запросов за `PACKAGE_PRICE_KOPEKS` (по умолчанию 69000 = 690 ₽), и приём оплаты. Без этого раздела сайт продолжает
работать как раньше — просто с анонимным бесплатным пейволлом, без аккаунтов и без покупки пакета.

Нужно завести 3 внешних сервиса — сама я аккаунты создать не могу (это делается только вручную, с вашей почтой/картой),
но весь код уже готов принять ключи. Ничего не ломается, если сделать это не сразу или по одному — каждый блок
работает независимо и до появления своих ключей просто отключён (сервер сам об этом предупреждает в логах).

### 5.1. База данных — Neon (бесплатно)

1. neon.tech → зарегистрироваться → **New Project** (регион ближе к Render, например Frankfurt).
2. На странице проекта — **Connection string** (или Dashboard → Connect) → скопируйте строку вида
   `postgresql://user:password@ep-xxxx.eu-central-1.aws.neon.tech/dbname?sslmode=require`.
3. В Render → `astro-backend` → **Environment** → добавьте `DATABASE_URL` = эта строка → Save.
4. При следующем деплое сервер сам создаст нужные таблицы (миграция в `db.js` запускается автоматически при старте).

### 5.2. Письма с кодом входа — Resend (бесплатно, 100 писем/день)

1. resend.com → зарегистрироваться → **API Keys** → создать ключ.
2. Без своего домена можно слать только с их адреса `onboarding@resend.dev` — этого достаточно для старта.
   Если позже подключите свой домен в Resend (Domains → Add Domain, впишете DNS-записи) — смените `MAIL_FROM`
   на что-то вроде `Ведическая астрология <noreply@ваш-домен.ru>`.
3. В Render → Environment → `RESEND_API_KEY` = ваш ключ. `MAIL_FROM` можно не трогать (есть значение по умолчанию).
4. Без этого шага код входа просто печатается в лог сервера на Render (Logs) — можно тестировать вход самой,
   заглядывая в логи, пока не подключите Resend по-настоящему.

### 5.3. Приём оплаты — ЮKassa для самозанятых

1. yookassa.ru → **Касса для самозанятых** (это отдельный, упрощённый продукт именно под НПД — чек в
   «Мой налог» формируется автоматически по вашему ИНН, без интеграции с кассовым чеком вручную).
2. Пройдите их регистрацию/подключение карты для самозанятой.
3. В личном кабинете ЮKassa — **Настройки → Магазин** (или «Ключи API») → скопируйте `shopId` и `Секретный ключ`.
4. В Render → Environment:
   - `YOOKASSA_SHOP_ID` = ваш shopId
   - `YOOKASSA_SECRET_KEY` = ваш секретный ключ
   - `PAYMENT_RETURN_URL` = адрес фронтенда с `?paid=1`, например `https://astro-gold-three.vercel.app/?paid=1`
5. В настройках магазина ЮKassa (там же, в разделе Уведомления/HTTP-уведомления) укажите адрес вебхука:
   `https://ВАШ-АДРЕС-BACKEND.onrender.com/api/pay/webhook` (тот же хост, что и остальной API).
6. Без этого шага кнопка «Купить пакет» работает в тестовом режиме: пакет сразу помечается оплаченным без
   реальных денег — так можно проверить весь остальной цикл (вход → лимит → списание) ещё до подключения ЮKassa.

### Проверка после всех трёх шагов

Зайдите на сайт → вкладка «Тарифы» → введите свой email → код придёт на почту (или найдётся в логах Render,
если Resend ещё не подключён) → войдите → нажмите «Купить пакет» → должно открыться окно оплаты ЮKassa.
После оплаты на вкладках «Совместимость», «Периоды жизни» (пратьянтардаша) и «Релокация» повторные/новые запросы
будут списывать из пакета вместо жёсткого тизера, а «Семья и дети» откроется целиком и навсегда.

Цену и размер пакета можно поменять в любой момент без нового кода — просто измените `PACKAGE_PRICE_KOPEKS`
(в копейках, 69000 = 690 ₽) и `PACKAGE_QUOTA` в Render → Environment.
